# VoiceFlow 职场语音意图输入助手

VoiceFlow 是一个 72 小时 MVP 原型，面向职场文字沟通场景。它不追求做完整系统级输入法，而是验证一个更窄的产品假设：用户只需要说出意图，系统就能把口语内容整理成得体、结构清晰、可直接发送的职场回复。

## 核心洞察

语音输入的效率瓶颈已经不只是"声音转文字"的速度。对职场用户来说，更慢的部分往往是：

- 怎么把口语想法组织成可发送文本。
- 怎么根据领导、同事、客户、下属调整语气。
- 怎么补齐时间、原因、下一步，避免沟通不清。
- 怎么减少识别后反复修改、润色、复制的成本。

因此，首版不拼 ASR 准确率，也不把"通用 AI 润色"包装成创新，而是主打"口述意图 → 职场回复"的完整链路。

## 当前功能

- 输入或模拟语音口述内容。
- 选择意图场景：同步进展、请求协作、拒绝协商、催促推进、确认回应。
- 选择沟通对象：领导、同事、客户、下属。
- 选择回复风格：简洁、礼貌、推进、正式。
- 展示生成依据：系统识别/采用什么职场意图、面向什么对象、使用什么表达策略。
- 自动提取结构化信息：结论、原因、时间、下一步。
- 生成三种回复版本：推荐版、简短版、增强推进版。
- 给出沟通风险提示：时间承诺、下一步、语气和边界。
- 支持编辑推荐回复和一键复制。

## 五类代表性意图

第二阶段新增五类职场意图场景，作为与沟通对象、回复风格并列的显式输入。当前为代表性分类，覆盖度需后续用户测试验证。

| 场景 | 说明 | 示例 |
|------|------|------|
| 同步进展 | 同步当前状态、原因和下一步 | 供应商还没确认，今天报价给不了，最快明天下午 |
| 请求协作 | 请求配合、请假交接或资源协调 | 我明天下午需要请假，客户资料我上午整理好，麻烦小王帮我跟一下群消息 |
| 拒绝协商 | 承接需求、说明限制、给替代方案 | 这个需求这周做不完，下周再排，可以先把优先级确认一下 |
| 催促推进 | 背景、阻塞点、需要的反馈和截止时间 | 报价单还没收到，麻烦今天下午五点前确认一下，不然会影响明天提报 |
| 确认回应 | 确认收到、复述关键信息、明确下一步 | 收到客户确认了新方案，我今天整理合同版本，明早发过去 |

## Demo 演示脚本

按以下顺序操作可完整体验五类职场场景的产品闭环：

### 1. 同步进展 — 向客户说明延期

1. 点击「模拟语音输入」切换到"客户报价延期"样例。
2. 确认意图场景为「同步进展」、沟通对象为「客户」、回复风格为「礼貌」。
3. 点击「生成职场回复」。
4. 观察：生成依据显示"基于你选择的「同步进展」职场意图"；结构化理解提取了供应商原因和时间点；风险提示包含时间承诺确认。
5. 点击「复制」复制推荐版回复。

### 2. 请求协作 — 向上级请假并交接

1. 点击「模拟语音输入」切换到"请假交接协作"样例。
2. 确认意图场景为「请求协作」、沟通对象为「领导」、回复风格为「正式」。
3. 点击「生成职场回复」。
4. 观察：风险提示中不会出现"缺少交接信息"（因为样例已包含交接安排）。
5. 修改文本框内容为"我明天下午需要请假"（去掉交接信息），再次生成，观察风险提示中出现了"缺少交接信息"。

### 3. 拒绝协商 — 向同事说明排期

1. 点击「模拟语音输入」切换到"需求排期协商"样例。
2. 确认意图场景为「拒绝协商」、沟通对象为「同事」、回复风格为「简洁」。
3. 点击「生成职场回复」。
4. 观察：结构化理解包含了重新排期的结论；输出有替代方案建议。
5. 修改文本框内容为"这个需求这周做不完"（去掉替代方案），再次生成，观察风险提示变化。

### 4. 催促推进 — 向客户催报价

1. 点击「模拟语音输入」切换到"催促报价反馈"样例。
2. 确认意图场景为「催促推进」、沟通对象为「客户」、回复风格为「礼貌」。
3. 点击「生成职场回复」。
4. 观察：生成依据说明了催促策略和礼貌表达的原因；风险提示包含催促客户时的语气提醒。
5. 修改文本框去掉截止时间，再次生成，观察风险提示中出现了"缺少截止时间"。

### 5. 确认回应 — 确认客户方案

1. 点击「模拟语音输入」切换到"确认客户方案"样例。
2. 确认意图场景为「确认回应」、沟通对象为「同事」、回复风格为「简洁」。
3. 点击「生成职场回复」。
4. 观察：结构化理解结论为"已收到并确认"；下一步识别了整理合同的具体动作。
5. 修改文本框内容为"收到"，再次生成，观察风险提示中出现了"缺少下一步动作"。

### 语境变化提示

1. 在已有生成结果的情况下，修改意图场景或沟通对象或回复风格。
2. 观察界面中出现黄色提示条"语境已变化，请重新生成回复"。
3. 已有结果不会被清除，用户可以对比不同参数下的输出差异。
4. 点击「生成职场回复」重新生成，提示条消失。

## Mock 说明

当前版本不接入真实语音识别和真实大模型。页面中的"模拟语音输入"使用预设职场口述样例，生成逻辑位于 `src/lib/generateReply.js`。

第二阶段仍是 Mock 生成。真实语音输入将在独立 PR #3 中实现。

后续可以替换为：

- Web Speech API 或第三方 ASR 服务。
- OpenAI、Claude、DeepSeek 等真实 LLM。
- 个性化术语库和联系人语气偏好。

## 隐私说明

首版 MVP 为纯前端演示，不把用户输入上传到后端。若后续接入云端 ASR 或 LLM，需要在 README 和产品界面中明确说明数据处理方式、保存策略和用户授权。

## 原创功能说明

本项目原创部分是围绕职场沟通场景设计的交互和 Mock 规则：

- 意图场景驱动的回复生成（同步进展、请求协作、拒绝协商、催促推进、确认回应）。
- 沟通对象驱动的语气适配（领导、同事、客户、下属）。
- 口述意图到结构化回复的转换（结论、原因、时间、下一步）。
- 生成依据展示（向评审说明系统为什么会这样理解）。
- 多版本职场回复（推荐版、简短版、增强推进版）。
- 场景化沟通风险提示。

通用 ASR、自动标点和基础 AI 润色被视为行业基础能力，不作为本项目的核心差异化。
