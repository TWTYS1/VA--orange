# VoiceFlow 职场语音意图输入助手

VoiceFlow 是一个 72 小时 MVP 原型，面向职场文字沟通场景。它不追求做完整系统级输入法，而是验证一个更窄的产品假设：用户只需要说出意图，系统就能把口语内容整理成得体、结构清晰、可直接发送的职场回复。

## 核心洞察

语音输入的效率瓶颈已经不只是"声音转文字"的速度。对职场用户来说，更慢的部分往往是：

- 怎么把口语想法组织成可发送文本。
- 怎么根据领导、同事、客户、下属调整语气。
- 怎么补齐时间、原因、下一步，避免沟通不清。
- 怎么减少识别后反复修改、润色、复制的成本。

因此，首版不拼 ASR 准确率，也不把"通用 AI 润色"包装成创新，而是主打"口述意图 → 职场回复"的完整链路。

## 当前功能

- 输入或模拟语音口述内容。
- 选择意图场景：同步进展、请求协作、拒绝协商、催促推进、确认回应。
- 选择沟通对象：领导、同事、客户、下属。
- 选择回复风格：简洁、礼貌、推进、正式。
- **真实语音输入**：通过本地代理将麦克风音频发送至阿里云百炼 DashScope Paraformer 实时识别，转写结果追加到文本框。未配置密钥时可使用文本输入和演示样例。
- 展示生成依据：基于用户选择的职场意图场景、沟通对象和表达策略解释生成结果。
- 自动提取结构化信息：结论、原因、时间、下一步。
- 生成三种回复版本：推荐版、简短版、增强推进版。
- 给出沟通风险提示：时间承诺、下一步、语气和边界。
- 支持编辑推荐回复和一键复制。

## 五类代表性意图

第二阶段新增五类职场意图场景，作为与沟通对象、回复风格并列的显式输入。当前为代表性分类，覆盖度需后续用户测试验证。

| 场景 | 说明 | 示例 |
|------|------|------|
| 同步进展 | 同步当前状态、原因和下一步 | 供应商还没确认，今天报价给不了，最快明天下午 |
| 请求协作 | 请求配合、请假交接或资源协调 | 我明天下午需要请假，客户资料我上午整理好，麻烦小王帮我跟一下群消息 |
| 拒绝协商 | 承接需求、说明限制、给替代方案 | 这个需求这周做不完，下周再排，可以先把优先级确认一下 |
| 催促推进 | 背景、阻塞点、需要的反馈和截止时间 | 报价单还没收到，麻烦今天下午五点前确认一下，不然会影响明天提报 |
| 确认回应 | 确认收到、复述关键信息、明确下一步 | 收到客户确认了新方案，我今天整理合同版本，明早发过去 |

## Demo 演示脚本

按以下顺序操作可完整体验五类职场场景的产品闭环：

### 1. 同步进展 — 向客户说明延期

1. 点击「模拟语音输入」切换到"客户报价延期"样例。
2. 确认意图场景为「同步进展」、沟通对象为「客户」、回复风格为「礼貌」。
3. 点击「生成职场回复」。
4. 观察：生成依据显示"基于你选择的「同步进展」职场意图"；结构化理解提取了供应商原因和时间点；风险提示包含时间承诺确认。
5. 点击「复制」复制推荐版回复。

### 2. 请求协作 — 向上级请假并交接

1. 点击「模拟语音输入」切换到"请假交接协作"样例。
2. 确认意图场景为「请求协作」、沟通对象为「领导」、回复风格为「正式」。
3. 点击「生成职场回复」。
4. 观察：风险提示中不会出现"缺少交接信息"（因为样例已包含交接安排）。
5. 修改文本框内容为"我明天下午需要请假"（去掉交接信息），再次生成，观察风险提示中出现了"缺少交接信息"。

### 3. 拒绝协商 — 向同事说明排期

1. 点击「模拟语音输入」切换到"需求排期协商"样例。
2. 确认意图场景为「拒绝协商」、沟通对象为「同事」、回复风格为「简洁」。
3. 点击「生成职场回复」。
4. 观察：结构化理解包含了重新排期的结论；输出有替代方案建议。
5. 修改文本框内容为"这个需求这周做不完"（去掉替代方案），再次生成，观察风险提示变化。

### 4. 催促推进 — 向客户催报价

1. 点击「模拟语音输入」切换到"催促报价反馈"样例。
2. 确认意图场景为「催促推进」、沟通对象为「客户」、回复风格为「礼貌」。
3. 点击「生成职场回复」。
4. 观察：生成依据说明了催促策略和礼貌表达的原因；风险提示包含催促客户时的语气提醒。
5. 修改文本框去掉截止时间，再次生成，观察风险提示中出现了"缺少截止时间"。

### 5. 确认回应 — 确认客户方案

1. 点击「模拟语音输入」切换到"确认客户方案"样例。
2. 确认意图场景为「确认回应」、沟通对象为「同事」、回复风格为「简洁」。
3. 点击「生成职场回复」。
4. 观察：结构化理解结论为"已收到并确认"；下一步识别了整理合同的具体动作。
5. 修改文本框内容为"收到"，再次生成，观察风险提示中出现了"缺少下一步动作"。

### 语境变化提示

1. 在已有生成结果的情况下，修改原始口述文本、意图场景、沟通对象或回复风格。
2. 观察界面中出现黄色提示条"语境已变化，请重新生成回复"。
3. 已有结果不会被清除，用户可以对比不同参数下的输出差异。
4. 点击「生成职场回复」重新生成，提示条消失。

## 技术栈

- Vite + React 前端
- Node WebSocket 代理
- 阿里云百炼 DashScope Paraformer（实时语音识别）
- Vitest 单元测试
- 纯前端 Mock 规则引擎（回复生成）

## 本地运行

```powershell
npm install
Copy-Item .env.example .env.local
# 在 .env.local 中填写 DASHSCOPE_API_KEY，不要提交该文件
npm run dev
```

一条命令同时启动前端 Vite 开发服务器和本地 ASR 代理。浏览器打开终端输出的本地地址即可体验。

未配置 `DASHSCOPE_API_KEY` 时，语音输入功能不可用，但仍可使用文本输入和演示样例完成完整的产品体验。

## 构建与测试

```bash
npm test
npm run build
```

## 真实语音输入

语音输入通过本地 Node 代理将麦克风音频发送至阿里云百炼 DashScope Paraformer (`paraformer-realtime-v2`) 进行实时识别，转写结果追加到文本框。

**数据流**：

```text
麦克风 → getUserMedia → AudioContext 重采样（16k mono PCM）
  → 本地 WebSocket 代理 (server/asrProxy.js)
  → DashScope WebSocket (paraformer-realtime-v2)
  → 转写文本追加到 rawText → 复用现有回复生成闭环
```

密钥通过 `.env.local` 注入服务端，不会进入浏览器 bundle。音频不在本地持久化。

### 语音输入演示步骤

1. 确保已正确配置 `.env.local` 中的 `DASHSCOPE_API_KEY`。
2. 执行 `npm run dev` 启动前端和代理。
3. 在支持麦克风的浏览器（Chrome/Edge）中打开页面。
4. 确认页面显示「语音输入可用」标签和「开始语音输入」按钮。
5. 点击「开始语音输入」，授予麦克风权限，说出职场口述内容。
6. 观察文本框下方显示临时识别结果。
7. 点击「停止录音」，最终识别文本追加到文本框，提示"语境已变化，请重新生成回复"。
8. 选择意图场景、沟通对象、回复风格，点击「生成职场回复」。

### 降级说明

未配置 `DASHSCOPE_API_KEY` 或 DashScope 连接失败时，可使用文本输入和「使用演示样例」完成完整体验。浏览器不支持麦克风时自动展示降级提示。

## Mock 说明

回复生成仍使用本地 Mock 规则引擎（`src/lib/generateReply.js`），不接入真实大模型。

语音输入时，麦克风音频通过本地代理发送至阿里云百炼 Paraformer 服务进行识别。本项目不在本地后端持久化保存音频或文本；数据处理还受阿里云服务策略约束。

后续可以替换为：

- OpenAI、Claude、DeepSeek 等真实 LLM 替代 Mock 规则引擎。
- 个性化术语库和联系人语气偏好。

## 隐私说明

当前版本不自建后端保存用户文本或音频。DashScope API Key 通过服务端环境变量注入，不会暴露到浏览器。语音识别数据由阿里云百炼服务处理，数据处理方式受阿里云服务策略约束。回复生成在当前版本中仍使用本地 Mock 规则，不向任何服务发送文本。

## 原创功能说明

本项目原创部分是围绕职场沟通场景设计的交互和 Mock 规则：

- 意图场景驱动的回复生成（同步进展、请求协作、拒绝协商、催促推进、确认回应）。
- 沟通对象驱动的语气适配（领导、同事、客户、下属）。
- 口述意图到结构化回复的转换（结论、原因、时间、下一步）。
- 生成依据展示（向评审说明系统如何基于用户选择生成回复）。
- 多版本职场回复（推荐版、简短版、增强推进版）。
- 场景化沟通风险提示。

通用 ASR、自动标点和基础 AI 润色被视为行业基础能力，不作为本项目的核心差异化。
